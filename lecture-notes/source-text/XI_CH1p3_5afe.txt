1.3.1 What is a Communication Model?
A communication model is a set of rules and layers that explains how data
(information) travels from one device to another through a network. Think of it like the
rules of a postal system; both the sender and the receiver must follow the same steps
Unit 1: Computer Systems
Why do we need communication models?
e
They allow computers from different companies and countries to talk to each
other.
e
They make it easier to find and fix problems in a network.
e
They divide a complex task into smaller, manageable steps called layers.
e
They allow engineers to design new technologies without breaking existing
ones.
Analogy: Sending data over a network is like sending a letter by post. You write the
message, put it in an envelope, write the address, hand it to the post office, which sorts
it and delivers it. Each step is like a layer in a communication model.
The two most important communication models are:
e
OSI Model (Open Systems Interconnection), a 7-layer reference model used
mainly for learning and design.
e
TCP/IP Model (Transmission Control Protocol / Internet Protocol), a 4-layer
model actually used on the Internet today.

Layer 5, Session Layer:
The Session Layer manages communication sessions between two computers.
A session is a connection that is established, maintained, and eventually terminated
between two devices. This layer ensures that a conversation, once started, can be
continued, paused, and resumed in an orderly way.
Real-life analogy: A telephone call, you say "Hello" to start, speak until you are done,
and say "Goodbye" to end. The session layer handles this opening, maintenance, and
closing.

Session Establishment: Sets up a session between two communicating devices.
Session Maintenance: Keeps the session active and coordinates data exchange.
Session Termination: Closes the session properly when communication ends.

if
interrupted, avoiding the need to restart from the beginning.
Dialog Control: Manages whether communication is half-duplex (one direction
at a time) or full-duplex (both directions simultaneously).

1.3.4 How Data Travels Through the OSI Layers:
When a user sends data (for example, loading a webpage), the data travels
downward through all seven layers on the sender's device. At each layer, additional
information called a header is added. This process is called encapsulation. When the
data arrives at the destination, it travels upward through all seven layers. At each layer,
the corresponding header
is read and removed.
This reverse process
is called

1.
Application Layer (TCP/IP):
The TCP/IP Application Layer combines the functions of the OSI Application,
Presentation, and Session layers into a single layer. It provides all the services that user-
facing applications need to communicate over the network, including data formatting,
encryption, session management, and the actual application protocols (HTTP, FTP,
SMTP, DNS, etc.).
2.
Transport Layer (TCP/IP):
Identical in function to OSI Layer 4. The Transport Layer provides end-to-end
communication services.
It uses TCP for reliable, connection-oriented delivery and
UDP for fast, connectionless delivery. Port numbers are used at this layer to identify
applications.

3.
Internet Layer (TCP/IP):
The Internet Layer corresponds to the OSI Network Layer. It is responsible for
logical (IP) addressing and routing packets across multiple networks. The Internet
Protocol (IP) is the core protocol at this layer. Routers operate at the Internet Layer to
forward packets toward their destinations.
4.
Network Access Layer (TCP/IP):
The Network Access Layer (also called the Link Layer) combines the OSI Data
Link and Physical layers. It handles everything related to the local physical network:
MAC addressing, framing, error detection, and the actual physical transmission of bits
over cables or wireless signals. Ethernet, Wi-Fi, and the underlying hardware all
operate at this layer.
