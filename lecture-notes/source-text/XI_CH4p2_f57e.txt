Selecting appropriate data types:
Choosing the correct data type for each field is a critical design decision. Data
types define the kind of values a field can store and influence both storage efficiency
and data validation.
Common data types in Microsoft Access include:
e
Short Text: Used for alphanumeric data such as names, addresses, and email
IDs.
Number: Suitable for numeric values used in calculations.
Date/Time: Stores date and time information.
Currency: Designed for financial values with precision.
AutoNumber: Automatically generates unique values, often used for primary
keys.
Selecting inappropriate data types can lead to data inconsistencies, increased
storage requirements, and limitations in performing operations.

Creating Queries in MS Access:
Queries are one of the most powerful features of Microsoft Access. They allow
users to retrieve, filter, and analyze data stored in tables based on specific conditions
or criteria. In a student database system, queries are particularly useful for extracting
meaningful information such as lists of students from a specific department, students
enrolled in a particular year, or records matching certain conditions.

Student table.
4.11.1 Introduction to Queries:
A query is a request to retrieve specific data from one or more tables based on
defined criteria. Instead of displaying all records, queries allow users to focus only on
relevant data.
Purpose of Queries:
e
Filter records based on conditions
Sort data in ascending or descending order
Display selected fields only
Perform simple calculations (in advanced cases)

department, students who scored above a certain mark, or records created within a
specific time period. To achieve this, we use data filtering techniques. Filtering allows
us to define criteria or conditions so that the query displays only the records that match

A database is composed of tables, which store data in rows and columns.
Each row is a record representing a single entity instance, and each column is a
field representing an attribute.
The primary key is used to uniquely identify each record, ensuring accuracy and
preventing duplication.
The Entity-Relationship (ER) Model provides
a way to represent real-world

foreign keys.
Mechanisms such as cascade update and cascade delete automatically maintain
consistency across tables.
A relational schema acts as a blueprint of the database.
Forms provide a user-friendly interface for entering, updating, and viewing data

Reports are used to present data in a formatted and organized manner, suitable
