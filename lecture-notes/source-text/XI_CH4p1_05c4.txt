Introduction to Unit:
This chapter helps students understand how data is organized, analyzed, and
used to make informed decisions, covering key concepts, real-world examples, and
digital tools.
Data is generated all around us through smartphones, online shopping, social
media, and smart cities. Organizations across every sector rely on it to plan and improve
services. However, data alone means nothing;
it becomes knowledge only when
analyzed.
For Example: A month of recorded temperatures is raw data but calculating
averages or spotting trends turns it into insight. That is data analysis.
In this unit, students will explore database concepts, real-world applications, and how
digital tools transform raw data into meaningful decisions.

Database
A database is an organized collection of related data that is stored in a structured
manner so that it can be easily accessed, managed, and updated. In traditional
systems, data was stored in files or books, which made it difficult to search,
update, or maintain consistency. A database solves these problems by providing
a systematic way to store and retrieve data.
4.1.2 Database Management System:
A Database Management System (DBMS)
is software that allows users to
create, manage, and interact with databases. It acts as a bridge between the user and the
database. Instead of directly handling data files, users interact with DBMS, which
performs operations such as inserting, updating, deleting, and retrieving data.
For example, in a school environment, a DBMS can be used to manage student data.
Instead of writing information in books, the school can store all student data in a
database. Teachers can quickly search for a student’s data, update marks, or generate
reports using the DBMS. DBMS provides the following advantages:
i)
Less Redundancy: Which means the same data is not stored multiple times
unnecessarily
For example, instead of storing a student’s department name in every table
(Student table, Exam table, Fee table), the department is stored once in the
Department table, and other tables refer to it using a DepartmentID.
ii)
Improved Data Consistency: which ensures that all users see the same correct
data
For example, if a student’s contact number is updated in the Student table, every
query, form, or report that accesses this table will automatically show the
updated contact number, so all users see the same information.
iii)
Improved Security: Allowing only authorized users
to
access
sensitive
information.
For example, only the admin or teacher can view students’ exam marks, while
general staff can only view names and contact details.
iv)
Data integrity: It ensures that the data stored in the database is accurate and
reliable.
For example,
a student’s roll number must be unique, and the system will
prevent duplicate entries.
Common examples of DBMS include Microsoft Access, MySQL, Oracle, and
SQL Server. These systems are widely used in educational institutions, businesses,
banks, and government organizations.

and marks.
The columns in a table are called fields. Each field represents a specific type of
data or attribute. For example, in a student table, fields may include StudentID, Name,

Entity Relationship Model (ER-Model):
The Entity Relationship (ER) Model
is
a conceptual tool used to design
databases before they are created. It helps in understanding what data needs to be stored
and how different pieces of data are related to each other. Designing a database without
proper planning can lead to errors, duplication, and inefficiency. Therefore, the ER
model plays a very important role in database development.
An ER model consists of three main components:
1.
Entities:
An entity is any real-world object or concept about which data is stored. For
example,
in
a school database, entities can include Student, Teacher, and
Course. These are things that exist independently and have their own identity.
2.
Attributes:
Attributes are the properties or characteristics of an entity. For example, the
Student entity may have attributes such as StudentID, Name, Class, and Marks.
These attributes provide detailed information about the entity.

Relationships:
Entities in a database are connected through relationships, which define how
data is stored and linked between tables in the ER model. Understanding these
relationships is essential for designing efficient and accurate databases.
There are three main types of relationships:
e
One-to-One (1:1): One record is related to only one record of another entity
(e.g., one student has one ID card). This is rare and used for separation or
security.
e
One-to-Many (1:M): One record is related to multiple records of another
entity (e.g., one teacher teaches many students). This is the most common
type.
e
Many-to-Many (M:N): Multiple records of one entity relate to multiple
records of another (e.g., students enroll in many classes, and classes have
many students).
Since relational databases do not directly support many-to-many relationships,
a junction
(bridge)
table
is used
to break them
into
two one-to-many
relationships.
For example, many students can enroll in many classes; therefore, this many-
to-many relationship is represented using a junction table (Enrolment), which
stores StudentID and ClassID to link students with their respective classes.
Properly defining relationships
ensures
logical
data organization,
avoids
redundancy, and improves data accuracy and retrieval.

Referential Integrity and Its Importance:
Referential integrity
is
a fundamental concept
in relational databases that
ensures the accuracy and consistency of data across related tables. When multiple tables
are connected using foreign keys, it is important that the relationships between them
remain valid at all times. Referential integrity ensures that a foreign key in one table
always refers to an existing and valid record in another table.
To understand this concept, consider a simple example of a school database
with two tables: a Student table and a Result table. The Student table contains student
details such as StudentID and Name, while the Result table contains marks along with
StudentID as a foreign key. Referential integrity ensures that every StudentID in the

table, the change is automatically updated in all related tables. In cascade delete, if a

Relational Schema Development:
A relational schema is a formal representation of the structure of a database. It
defines how data is organized into tables, what fields each table contains, and how
different tables are related to each other. In simple terms, a schema acts as a design of
the database before it is implemented.
Developing a relational schema is an important step in database design because it helps
in
organizing
data
logically
and
efficiently.
A well-designed
schema
reduces
redundancy, improves data integrity, and makes the database easier to manage.
To understand relational schema development, consider a school database system.
e
Initially, we identify the main entities such as Student, Course, and Teacher.
Each of these entities will be represented as a table in the database. For example,
the student table may contain fields such as StudentID, Name, Class, and
Address. Similarly, the Course table may include CourseID and CourseName.
e
After identifying tables, the next step is to define relationships between them.
For example,
students
enroll
in courses.
Since
this
is
a many-to-many
relationship, we create an additional table called Enrollment. This table contains
StudentID and CourseID as foreign keys, linking the Student and Course tables.
e
Another important aspect of schema design is defining keys. Each table must
have a primary key that uniquely identifies its records. Foreign keys are used to
establish relationships between tables.

Creation of Tables in Microsoft Access:
Creating tables is the fundamental step in developing a database system, as
tables serve as the primary structure for storing and organizing data. A carefully
designed table not only ensures data accuracy and consistency, but also improves query
performance, storage efficiency, and ease of data retrieval. Poor table design, on the
other hand, can lead to redundancy, inconsistency, and difficulty in maintaining the
database.
4.9.1 Planning the Table Structure:
Before physically creating
a table
in Microsoft Access,
it
is important to
perform proper planning. This step ensures that the table structure aligns with the
requirements of the system and avoids future modifications.
Key planning activities include:
e
Identifying the Purpose of the Table: Clearly define what information the
table will store and how it will be used.
e
Listing Required Fields: Determine all attributes necessary to represent the
entity completely.
e
Selecting Appropriate Data Types: Choose data types that match the nature
of the data (e.g., text, numeric, date).
e
Determining the Primary Key: Identify a field (or combination of fields) that
uniquely identifies each record.
