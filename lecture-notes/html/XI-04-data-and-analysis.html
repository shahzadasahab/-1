0. Data is not yet knowledge

Data are unprocessed facts — numbers, text, images — quantitative (countable/measurable) or qualitative (descriptive). Information is data after organising, processing, and interpreting. A database is an organised, stored collection that a program can retrieve without hunting through notebooks.

\[ \text{Data} \;\xrightarrow{\;\text{processing}\;} \text{Information} \;\xrightarrow{\;\text{organisation}\;} \text{Database} \]

Raw: $80,75,90,70,85$. Information: class average $=80\%$.

1. DBMS — the software that looks after the boxes

A Database Management System (MS Access, MySQL, Oracle, SQL Server) stores, protects, and retrieves data. Benefits: less redundancy, consistent copies, security, integrity constraints.

2. Keys and relationships — how tables refuse to become spaghetti

A candidate key is any field (or minimal set) that uniquely identifies a record. You promote one candidate to primary key (PK). The unused candidates become alternate keys. A foreign key (FK) in table B stores a PK value from table A so the two rows belong together.

Table 2. The three relationship cardinalities
TypeMeaningHow we store it
$1:1$Each A matches at most one BPK of A also stored (uniquely) in B
$1:M$One A, many B — the common caseFK of A sits in B
$M:N$Many A related to many BBreak with a junction / bridge table that holds both FKs

Students and classes are $M:N$ (a student takes many classes; a class has many students). The bridge Enrolment(StudentID, ClassID) turns that into two $1:M$ links.

2.1 Referential integrity

A foreign key value must already exist as a primary key, or be empty if the design allows it. You cannot loan a book that is not in BOOKS. Cascade update rewrites child FKs when a parent PK changes. Cascade delete removes child rows when the parent dies — use it only when those children have no meaning alone (loan rows without a student).

3. Entity-Relationship modelling

An entity is a real-world thing we store (Book, Member). An attribute is a property. A relationship is a verb between entities (Member borrows Book). Draw rectangles for entities, ovals or listed fields for attributes, diamonds or labelled lines for relationships, and mark PKs.

3.1 Library case — from story to schema

A library lends many books to many members. Direct $M:N$ is illegal in a pure relational schema, so we introduce BorrowRecord.

\[ \begin{align*} \text{Book}&(\underline{\text{BookID}}, \text{Title}, \text{Author}, \text{Publisher})\\ \text{Member}&(\underline{\text{MemberID}}, \text{Name}, \text{ContactInfo})\\ \text{BorrowRecord}&(\underline{\text{BorrowID}}, \text{MemberID}, \text{BookID}, \text{BorrowDate}, \text{ReturnDate}) \end{align*} \]

Underlined fields are primary keys. MemberID and BookID in BorrowRecord are foreign keys.

4. Database objects in MS Access

Access (and most desktop RDBMS tools) expose four objects students must name:

Tables
Store the data. Created in Datasheet View (spreadsheet-quick, weak control) or Design View (name every field, pick a data type, set the PK).
Forms
Friendly data-entry windows. Form Wizard can build a student registration screen on top of a table.
Queries
Questions: filter Department = "BCA", sort, pick columns, group, average.
Reports
Printable summaries and charts from selected data — what a principal actually reads.

Self-check

  1. Marks $70,80,90$ are data. Write one sentence of information.
  2. Why is $M:N$ stored with a third table?
  3. Cascade delete on Member $\to$ BorrowRecord: what happens if we delete a member who still has open loans?
Answers. (1) e.g. “The mean mark is $80$, so the class met the pass threshold.” (2) A relational table cannot hold a repeating group of other keys cleanly; the junction table stores each pair once. (3) Those loan rows disappear too — which may be wrong if you still need history. Prefer restrict/cascade-update unless history is disposable.

Recap

  1. Data $\to$ information $\to$ database. DBMS reduces redundancy and enforces rules.
  2. Table / record / field. PK unique; FK points at a PK.
  3. $1:1$, $1:M$, $M:N$ (junction). Referential integrity + optional cascades.
  4. ER: entities, attributes, relationships. Library: Book, Member, BorrowRecord.
  5. Access objects: tables, forms, queries, reports. Prefer Design View for real tables.
