1. Correctness — prove it by hand before you trust it

An algorithm is correct when every valid input produces the specified output and the process stops. Two classroom tools:

Trace table
A dry-run grid: line number, each variable, condition true/false, input/output. Best for loops and arithmetic slips. High effort for large $n$, so use a tiny example (soldier heights between $1.57$ and $1.91\,\mathrm{m}$).
Stepwise reasoning
Argue the invariant: “after $k$ steps, $S$ holds the sum of the first $k$ integers.” Catches structural bugs (forgot $N=0$) that a short trace might miss.

2. Clarity — modularity and readability

Modularity: one function, one job (Single Responsibility), loose coupling, abstraction. CalculateSum() and FindAverage() beat a 40-line blob.

Readability: velocity = distance / time documents itself. Consistent names, shallow nesting, indentation, comments only where the why is not obvious.

Refine for clarity: rename, extract a module, flatten a condition. Refine for efficiency: fewer steps, stop early (short-circuit), cache a repeated calculation, pick a better structure.

3. Efficiency — counting the work

Cost has two axes: time (steps as $n$ grows) and space (extra memory). Drivers: number of steps, number of conditions, number of repetitions. Ask: does it scale? where is the bottleneck? is the cost worth the gain?

Repetition hierarchy: logarithmic (excellent) $\to$ linear (good) $\to$ quadratic (poor for large $n$). Short-circuit a compound test when the first clause already decides it.

4. Data structures — the furniture the algorithm sits on

A data structure is an organised way to store and retrieve values. Choose it from the problem’s verbs, not from fashion.

4.1 Linear structures

Array
Fixed sequence, index $0..n-1$, access $O(1)$. Painful insert/delete in the middle. Classroom chairs with painted numbers.
Linked list
Nodes of (data + pointer). Walk from the head. Easy insert once you are there; no jumping. Browser back/forward history.
Stack · LIFO
PUSH adds on top; POP removes from top. Undo, plate pile, function-call return.
Queue · FIFO
Enqueue at rear; Dequeue from front; both $O(1)$ with two pointers. Printer line, ticket window.

4.2 Non-linear structures

Tree

A hierarchy from one root. Each child has one parent. Family tree, organisation chart, folder tree.

Graph

Vertices (nodes) plus edges (links). No forced hierarchy. Social network, road map (cities = nodes, roads = edges). Many routes may exist.

4.3 Shared operations and retrieval traces

Insert, delete, traverse, search, sort — every structure supports some of these with different costs.

  • Array retrieval: jump to an index, or scan forward/back.
  • List retrieval: start at the head; walk pointers by position or by key. There is no $A[i]$ jump.
  • Queue retrieval: the only honest removal is from the front.

Self-check

  1. Why is binary search $O(\log n)$ while scanning an unsorted list is $O(n)$?
  2. PUSH $10$, PUSH $20$, POP, PUSH $30$. What does a second POP return?
  3. A college wants the fairest print spooler. Stack or queue?
Answers. (1) Each binary probe discards half; a scan may look at every cell. (2) $30$ (the stack is $[10,30]$ after the first pop-and-push). (3) Queue — FIFO is fairness.

Recap

  1. Correctness: trace table + stepwise reasoning + edge cases.
  2. Clarity: modules, names, shallow control flow.
  3. Efficiency: $O(1), O(\log n), O(n), O(n^2)$; watch nested loops.
  4. Array $O(1)$ index; list walks; stack LIFO; queue FIFO $O(1)$ enqueue/dequeue.
  5. Trees branch from a root; graphs connect freely. Match structure to the problem’s verb.
