Stairs and ramps — analog versus digital

TODAY YOU WILL BE ABLE TO
  • Tell a discrete quantity from a continuous one.
  • Read a sine-like analog wave and a two-level digital wave.
  • Explain why a noisy digital 1 is rewritten as a clean 1.
OPENING PICTURE
A classroom has 31 students, never 31.4. Temperature can be 31.4 °C. That is the whole lecture in one pair of examples.

Discrete landings, continuous ramps

A discrete quantity takes separate countable values. You can point to each one. A continuous quantity can sit anywhere in a range: height, time, speed, voltage on a microphone wire.

Digital electronics copies the stairs. A wire is treated as LOW (\(0\)) or HIGH (\(1\)). Everything between is noise, not a third legal value. That is why a USB copy of a photo stays sharp: a slightly damaged 1 is still recognised as 1 and rewritten as a perfect 1.

Boolean algebra — arithmetic with truth

TODAY YOU WILL BE ABLE TO
  • Evaluate AND, OR, and NOT on given bits.
  • Apply precedence: parentheses → NOT → AND → OR.
  • Show the three intermediate values of a compound expression.
LAST LECTURE
Digital means two legal levels, \(0\) and \(1\). Today those two levels become an algebra.

George Boole (1850s) built an algebra with only \(\mathrm{FALSE}=0\) and \(\mathrm{TRUE}=1\). Variables \(A, B, C\) hold one of those values. Three primitive operations generate every digital circuit you will meet this year.

  • AND (\(\cdot\)) — \(Y=A\cdot B=1\) only if every input is 1. Two locks on one door.
  • OR (\(+\)) — \(Y=A+B=1\) if any input is 1. Two doors into one room.
  • NOT (\(A'\) or \(\overline{A}\)) — flips one bit. A light switch.
\[ (\,) \;\to\; \text{NOT }(\,'\,) \;\to\; \text{AND }(\,\cdot\,) \;\to\; \text{OR }(\,+). \]

Worked evaluations — write the middle steps

A. \(Y=A'+B\) with \(A=1,\,B=0\). First \(A'=0\). Then \(0+0=0\). So \(Y=0\).

B. \(Y=(A+B)\cdot C\) with \(A=1,\,B=0,\,C=1\). Parentheses: \(1+0=1\). Then \(1\cdot 1=1\). So \(Y=1\).

C. \(Y=A\cdot B+C'\) with \(A=B=C=1\). NOT first: \(C'=0\). AND: \(1\cdot 1=1\). OR: \(1+0=1\).

DO NOW (on paper)
Evaluate \(Y=(A\cdot B)'+C\) for \(A=1,B=1,C=0\). Write NAND first, then the OR. Answer: NAND of \(1,1\) is \(0\); \(0+0=0\).
COMMON MISTAKE
Treating \(+\) as ordinary plus. In Boolean algebra \(1+1=1\), not 2. There is no ‘2’ on a digital wire.
EXIT TICKET
1. State precedence in four words. 2. Evaluate \(Y=A'+B\) for \(A=0,B=0\). 3. Why is NOT called unary?
HOMEWORK
Make a three-column table: expression / values / \(Y\) for the three worked examples, covering the answers first.

TODAY YOU WILL BE ABLE TO

LAST LECTURE
AND needs every 1; OR needs any 1; NOT flips. A gate is that algebra in hardware: one or more inputs, exactly one output.

With \(n\) inputs a truth table has \(2^n\) rows. Always list inputs in binary counting order so no row is skipped: \(00,01,10,11\).

Derived identities you must be able to write:

NAND and NOR are universal: any Boolean function can be built from only NAND, or only NOR. XOR is the difference detector (two-way landing light). XNOR is the sameness detector.

RECITE

Karnaugh maps — grouping the ones

TODAY YOU WILL BE ABLE TO
  • Place minterms on a 2- and 3-variable K-map in Gray-code order.
  • Group \(2^n\) ones, including wrap-around.
  • Read the simplified product from a group.
LAST LECTURE
SOP writes one product per 1-row. A K-map is that same census drawn so neighbours differ by one bit and cancel.

Adjacent cells — including wrap-around — differ by one bit. That order is Gray code. Group 1, 2, 4, 8 ones (powers of two). The variable that changes inside the group disappears.

DO NOW
Simplify \(Y=\sum m(0,1,2,3,5,7)\). Two groups of four give \(Y=A'+C\).

Wrap-around trap: \(Y=\sum m(0,2,8,10)\) occupies the four corners. Shared literals are \(B'\) and \(C'\); \(A\) cancels. Result \(Y=B'C'\). Forget wrap-around and you leave four lonely minterms — the classic exam miss.

EXIT TICKET
1. Why must columns be Gray-coded? 2. Legal group sizes? 3. What happens to a variable that changes inside a group?
HOMEWORK
K-map \(Y=\sum m(1,3,5,7)\). It should collapse toward \(C\). Check your column order before you celebrate.

Waterfall versus Agile — Al-Noor cases

TODAY YOU WILL BE ABLE TO
  • Match Waterfall to a frozen, well-specified project.
  • Match Agile/Scrum to unclear, evolving features.
  • Retell both Al-Noor stories in six sentences.
LAST LECTURE
Six phases, CAPP, SRS. Today: two ways to walk those phases — one way down, or in short sprints.

Al-Noor Library — why Waterfall worked

1,200 students, 2,400 books, a paper register, lost copies. Requirements were frozen: add/edit books, search, 14-day loans, overdue alerts, printed reports, offline Windows. Team of four, six months, Python + Tkinter + SQLite. Nothing experimental was asked, so Waterfall fitted. Black-box testing found a search crash on misspellings and an overdue alert that ran only if a button was clicked. A two-week pilot sat on the librarian’s desk. Later: printer-driver fix (corrective), e-book category (adaptive), faster search (perfective), daily USB backup (preventive). Overdue returns fell about 70%.

Al-Noor Student App — why Agile worked

Nobody could list every feature on day one. Five two-week sprints, Flutter, five-person Scrum team. Sprint 1 shipped login + timetable; teachers’ names arrived from feedback. Sprint 2 shipped results; parents then asked for full attendance. Sprint 3’s SMS gateway died for two days — the team switched to email and kept moving. Sprint 4 connected to the library API in thirty minutes. Sprint 5 shipped homework photos. Five of ten original stories shipped in ten weeks. That flexibility is the point of Agile.

DECISION RULE (4-mark compare)
Pacemaker firmware with a frozen regulator spec → Waterfall (late change can kill). A club-events app that will grow with student requests → Agile. Four lines in a notebook is a complete answer.

Bubble Sort — neighbours swap

TODAY YOU WILL BE ABLE TO
  • Trace Bubble Sort on a 5-item list, pass by pass.
  • Write the nested-loop pseudocode.
  • State one strength and one weakness.
LAST LECTURE
An algorithm is finite steps. Today the steps compare neighbours until the list is ordered.

Walk along the list. Whenever two neighbours are in the wrong order, swap them. After pass \(k\), the \(k\) largest items sit at the right. Nested loops give time that grows like \(n^2\).

FOR pass ← 0 TO n−2
    FOR i ← 0 TO n−2−pass
        IF DATA[i] > DATA[i+1] THEN swap

Diary of {8, 4, 1, 9, 3}: pass 1 ends {4, 1, 8, 3, 9}; pass 2 ends {1, 4, 3, 8, 9}; pass 3 ends {1, 3, 4, 8, 9}; pass 4 confirms.

Strengths: easy to see; in-place; stable (equal keys keep their order). Weaknesses: many swaps; hopeless for large \(n\).

Studio list \(\{6,2,5,1\}\): pass 1 → \(\{2,5,1,6\}\) (three swaps); pass 2 → \(\{2,1,5,6\}\); pass 3 → \(\{1,2,5,6\}\).

EXIT TICKET
1. After pass 1, where does the largest item sit? 2. Why is the inner loop shorter each pass? 3. Is Bubble Sort stable?
HOMEWORK
Trace {8, 3, 6, 2} on paper. Show the list at the end of each pass. Count swaps.

Selection Sort — park the minimum

TODAY YOU WILL BE ABLE TO
  • Trace Selection Sort on the same list as Lecture 10.
  • Explain why it usually swaps less than Bubble Sort.
  • State that it is not stable.
LAST LECTURE
Bubble Sort swaps neighbours and parks the largest at the right. Selection Sort parks the next minimum at the left — at most one write per pass.

On pass \(k\), find the minimum of the unsorted tail and swap it into index \(k\). Still \(\Theta(n^2)\) comparisons, fewer writes, not stable.

  • Pass 0: smallest of the whole list is 1; swap with 8 → {1, 4, 8, 9, 3}.
  • Pass 1: smallest of the tail is 3; swap with 4 → {1, 3, 8, 9, 4}.
  • Pass 2: smallest of the tail is 4; swap with 8 → {1, 3, 4, 9, 8}.
  • Pass 3: smallest of the tail is 8; swap with 9 → {1, 3, 4, 8, 9}.

On \(\{6,2,5,1\}\) Selection finds min \(1\) and swaps once with \(6\) → \(\{1,2,5,6\}\). Watch equal keys: sort {9, 4, 7, 4, 1}. Bubble Sort should keep the first 4 ahead of the second. Selection Sort may swap their order — that single observation is a 3-mark “disadvantage” answer.

TEXTBOOK COUSIN
Some traces swap as soon as a smaller value is seen. Standard selection finds the index of the minimum, then swaps once. In the paper, follow the version your teacher traced.
EXIT TICKET
1. How many swaps per pass in standard Selection Sort? 2. Why is it not stable? 3. Same time class as Bubble Sort?
HOMEWORK

Linear search and binary search

TODAY YOU WILL BE ABLE TO
  • Trace linear search on unsorted data.
  • Compute mid and discard a half on a sorted list.
  • Say when binary search is simply wrong.
LAST LECTURE
Two sorts, both \(n^2\). Searching asks a different question: is this value here, and where?

Linear search checks items \(1,2,\ldots,n\). Works on unsorted data. Worst case \(n\) probes.

Binary search requires a sorted array. Each step uses

\[ \mathrm{mid} = \left\lfloor \frac{\mathrm{low}+\mathrm{high}}{2} \right\rfloor. \]

If the target is smaller, set \(\mathrm{high}=\mathrm{mid}-1\); if larger, \(\mathrm{low}=\mathrm{mid}+1\). About \(\log_2 n\) probes — twenty looks for a million items.

Find 11 in \(\{2,5,7,11,13,17,19\}\): \(\mathrm{mid}=\lfloor(0+6)/2\rfloor=3\), hit on the first probe. Find 2 (left edge): three looks. Find 12 (absent): finish with \(\mathrm{low}>\mathrm{high}\) and report not found — write that failure case so you do not invent a crash.

Binary search on an unsorted list is not “a bit worse.” It is wrong: the discarded half may hold the target. {9, 1, 4, 7} is a 2-mark trap.

A computer does exactly what you said, including the mistakes. Python is this course’s high-level language because it reads almost like English.

Low-level sits next to the machine (binary, assembly). Mid-level (C) lets you touch memory. High-level (Python, Java) hides the hardware so you think about the problem. C++ is for speed; Java’s promise is “write once, run anywhere”; Python’s promise is readable syntax and a huge library world.

An IDE is one workplace: editor, colour, run, debugger. VS Code becomes an IDE when you install the Microsoft Python extension. Save as program.py. Indentation is syntax: 4 spaces per block. Mix tabs and spaces and you will meet IndentationError.

Repetition — for, while, break, continue

TODAY YOU WILL BE ABLE TO
  • Choose for when the trip count is known.
  • Choose while until a condition dies.
  • Trace a while-loop that never dies.
LAST LECTURE
Selection picks one path. Repetition walks a path many times.

for when the count is known: range(start, stop, step) — stop is exclusive. while until a condition becomes False. break leaves now; continue skips this iteration.

for i in range(1, 6):
    print(i)          # 1 2 3 4 5

i = 1
while i < 6:
    print(i)
    i += 1            # without this line the loop never dies
LOGICAL ERROR, NOT A CRASH
The textbook infinite loop: i = 1; while i < 6: print(i); i -= 1. Trace: 1, 0, −1… \(i\) never reaches 6. The program is legal and will run until you kill it. Always ask: “What makes the condition False, and does every path reach it?”

A one-shot guess uses random.randint and a single if. A PIN loop (next lecture) uses while + a bool flag.

Referential integrity and Access objects

TODAY YOU WILL BE ABLE TO

LAST LECTURE
M:N is two 1:M links through a junction. Those links only work if every foreign key points at a living parent.

Referential integrity: every foreign key must match a living parent. You cannot store marks for StudentID 999 if that student does not exist.

Cascade update rewrites child FKs when the parent PK changes. Cascade delete removes child rows when the parent is deleted — use it like a chainsaw. Cascade-delete of a doctor wipes appointment history; better to forbid the delete or mark the doctor inactive.

Access objects: table stores, form enters, query asks, report prints. Create a table in Datasheet or Design view; pick datatypes (Short Text, Number, Date/Time, Currency, Yes/No, AutoNumber for a surrogate PK).
